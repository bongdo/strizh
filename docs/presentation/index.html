Strizh

01 · Проблема

Go-экосистема без Go-церемоний.

Strizh не заменяет Go. Он даёт другой фасад для тех же библиотек: меньше форм, меньше шума, больше намерения в коде.

01

Ошибки — значения

T or error и три формы or. Никаких исключений, try и catch.

02

Конкурентность — блок

par, par for … limit, within. Никаких go, chan, select, async/await.

03

Go — напрямую

Тот же use, те же Go-типы и интерфейсы. Никакого отдельного FFI-слоя и ручных адаптеров.

В прикладном коде нет видимого context. Нет «цвета функций». Нет unsafe.

02 · Принципы

Меньше механизмов — меньше способов сделать одно и то же.

01

Язык приложений

Не системный язык: нет unsafe, арен и C-backend. Задача — приложения, а не ядро ОС.

02

Значения и срезы

T[], T[N], map[K, V], append. GC и Go speed; без ручного управления памятью.

03

Один способ

Нет :=, switch, UFCS, export, методов снаружи типа. Один способ — меньше выбора.

04

Минимум синтаксиса

Каркас: var, ;, точка, or, match, par, within. Остальное — библиотеки.

05

Sum types закрыты

Enum sealed. match исчерпывающий. Компилятор знает, что вариантов больше нет.

06

FFI без адаптеров

Go-имена остаются Go-именами. use и есть граница.

Цель — не заменить Go. Цель — убрать из прикладного кода всё, что не является задачей.

03 · Синтаксис

Каркас: импорты, значения, формы типов.

Точка выбирает, скобки вызывают. Тип — в значении; var всегда с initializer.

Формы типов

ФормаСмысл
T[]срез
T[N]массив на N
T[U]generic-применение
map[K, V]map
*Tуказатель
fn(A) Rфункция
T or errorрезультат с ошибкой

T[] — и срез, и лист. Отдельного Vec нет: растёт через append.

03 · Синтаксис

Данные и методы живут вместе.

Поля и методы — внутри типа. Получатель всегда *T и никогда не пишется в сигнатуре.

Правила

  • self — неявный *T; в сигнатуре его нет.
  • Поля доступны по имени. self.field — когда имя перекрыто.
  • Метод нельзя добавить снаружи типа; override и embedding нет.
  • Value receiver нет. Чтение по значению — свободная функция.

03 · Синтаксис

Sum type, который действительно закрыт.

Enum — sealed-тип. match обязан покрыть все варианты; _ для enum не нужен.

Вариант без полей — Empty,. Конструктор — Shape.Circle { radius = 2.0 }. _ для enum не нужен: match обязан покрыть все варианты.

03 · Синтаксис

Ошибка — значение. or — форма обращения с ним.

Никаких исключений. defer привязан к блоку, а не к функции: цикл не течёт.

Три формы or

  • call() or return; — вернуть ошибку наверх.
  • call() or err { ... }; — обработать здесь; err — значение ошибки.
  • call() or panic("..."); — упасть с сообщением.

defer в цикле закрывает ресурс на каждой итерации, а не копит дескрипторы до конца функции. or return и паника тоже проходят через defer.

03 · Синтаксис

Generic без новых скобок. Пока без constraints.

Параметры — в [...] после имени. На вызове типы выводятся; явные аргументы — когда без них никак.

Ограничения (comparable, numeric) — в GAPS.md. В 0.2 их нет: операцию, которой нужен constraint, отвергнет Go.

04 · Новое в 0.2

Списки результатов — не tuple.

Результаты — это форма вызова, а не значение. Нельзя положить в переменную, проиндексировать или передать как аргумент.

Синтаксис

  • В объявлении — через запятую: fn f() A, B or error = { ... };
  • В типе функции — в скобках: fn(i32) (str, bool).
  • T or error — сахар для последнего error.

Чего нет

  • Нет tuple-типов и tuple-значений.
  • Нет индексации p[0] и вложения в аргументы.
  • Нет «вернуть пару» как одно значение.

04 · Новое в 0.2

Type-паттерны для any и интерфейсов.

Для enum остаются variant-паттерны. Для открытых типов появляется as, проверка без связывания и else.

Три формы

  • case T as x => ... — проверить тип и связать значение.
  • case T => ... — проверить тип без связывания.
  • else => ... — значение по умолчанию для открытого типа; вместо case _.

Границы

  • Только для any и интерфейсов. Enum — по-прежнему case Circle { radius }.
  • any открыт: исчерпываемость невозможна, else обязателен.

0.1: type switch нет; tea.Msg обрабатывается только через Go-колбэки. 0.2: match с as, проверкой типа и else.

04 · Новое в 0.2

nil без типа, self без шума.

Голый nil — там, где ожидаемый тип уже известен. self остаётся неявным получателем-указателем.

Правило

  • Известен ожидаемый тип — можно nil: return nil;, return self, nil;, аргумент.
  • Неоднозначно — nil[T]: var cmd = nil[tea.Cmd];.
  • nil — для указателей, срезов, map, функций и интерфейсов.

0.1: return nil[tea.Cmd]; → 0.2: return nil;

Правило

  • self — неявный *T; в сигнатуре не пишется.
  • Поля доступны без него; self нужен, когда возвращаешь/передаёшь получателя или есть перекрытие имени.

0.1 → 0.2: без изменений.

05 · Конкурентность

Конкурентность — блок, а не протокол.

Внутри par — независимые операторы. На } блок дожидается всех; утечь нечему.

Правила

  • or return, or panic или паника в одном операторе отменяет остальные; побеждает ошибка с низшим ord.
  • Захваченное состояние читается параллельно. Писать можно в переменную с одним писателем, если её не читает другой оператор, в слот итерации или через sync/atomic.
  • Запись через указатель, в map и в self запрещена. defer, within и or panic внутри работают: у каждого воркера свой defer stack и recovery boundary.
  • Вложенный par разрешён.

Никаких go, chan, select. Никакого context в сигнатурах. par создаёт и отменяет контекст сам. Core G1–G9 закрыт; динамический оракул — go build -race (G11).

05 · Конкурентность

par for с потолком. within с дедлайном.

limit ограничивает ширину цикла. within — область работы целиком. Оба прячут context.

Правила

  • limit N — потолок одновременных итераций; по умолчанию — GOMAXPROCS.
  • Ошибка отменяет остальные; возвращается ошибка с наименьшим индексом. Для map индекса нет: побеждает первая дошедшая.
  • within работает и без par; вложенность берёт минимальный дедлайн; внутри воркера дедлайн не меняет соседей.
  • par for (var x in xs) работает так же.
  • defer блочный: в обычном цикле ресурс закрывается на итерации; внутри par — свой stack воркера, очистка на его выходе.

Порядок результатов определяет вызывающий код, а не порядок завершения. limit и within — раздельные конструкции.

06 · Go interop

Bubble Tea без Go-адаптера.

tea.Model — обычный Go-интерфейс. *Model реализует его структурно: три метода, ни одного ctx.

Что здесь важно

  • Update возвращает tea.Model, tea.Cmd — список результатов.
  • tea.KeyPressMsg as k — type-паттерн по tea.Msg.
  • return self, nil; — голый nil для известного tea.Cmd.
  • tea.NewProgram(&m) — методы указательные, *Model реализует интерфейс.

В 0.2 ручной Go-адаптер не нужен. Если методу нужен hidden context, G10 генерирует non-ctx обёртку с точной Go-сигнатурой; отдельного adapter-файла нет.

Фоновые таймеры и IO для Bubble Tea не нужны: Cmd запускает сам tea.Program.

06 · Go interop

G10: context, которого нет в коде.

par и within — фича языка. Context остаётся внутри кодогена, даже когда метод реализует Go-интерфейс.

Strizh
fn Update(msg: tea.Msg) tea.Model, tea.Cmdодин метод, без ctx
тело с par / withinбез ctx в сигнатуре
→
zz_strizh.go
Update(...) — публичная обёрткаточная Go-сигнатура
_s_Model_Update_ctx(self, _s_ctx, …) — телоздесь живут par / within

Что делает кодоген

  • Генерирует обёртку с точной Go-сигнатурой.
  • Внутренняя версия получает скрытый ctx и вызывает par/within.
  • Обёртка скрыта в zz_strizh.go; пользователь пишет один метод.

Что это открывает

  • par/within внутри методов Go-интерфейсов.
  • Включая tea.Model.Update.
  • В app-коде ctx не появляется.

Статус: 0.2, реализовано. Публичная обёртка сохраняет точную Go-сигнатуру, внутренняя ctx-версия держит `par`/`within`. Через границу пакета или function value дедлайн не переносится.

08 · Границы

0.2 — вертикальный срез, а не весь gap list.

Списки результатов, type patterns, bare nil, G10, typecheck и par core. Всё остальное — осознанно позже.

В 0.2 закрыто

  • Списки результатов в объявлениях и типах функций.
  • Type-паттерны и else для any/интерфейсов.
  • Голый nil там, где тип известен.
  • G10: обёртки для скрытого context.
  • G1–G9: panic recovery, per-worker defer/within, write rules.
  • G26/G27: typecheck в check/LSP, method sets.
  • Conformance-тесты на новые формы.
  • Bubble Tea smoke: Init/Update/View.
  • self остаётся неявным.

Сознательно не делаем

  • Полный GAPS.md.
  • Tuple-значения и tuple-типы.
  • Generic constraints.
  • Generic enums.
  • Variadics.
  • Expression-level or.
  • LSP refactors: rename, references, actions.
Решение для всего — решение ни для чего.
