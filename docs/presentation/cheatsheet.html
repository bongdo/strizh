01 Файлы, пакеты, импорты

  • Файлы .str, UTF-8. Один каталог — один пакет; отдельной package-строки нет.
  • Корень проекта — каталог с strizh.toml. Корневой пакет компилируется как package main и обязан иметь fn main.
  • Видимость по первой букве: User — public, user — private. Имена _s_* зарезервированы кодогеном.

strizh.toml

name = "hello"
module = "example.com/hello"

Импорты

use fmt;
use os;
use "./lib" as lib;
use "charm.land/bubbletea/v2" as tea;
  • use fmt; — Go stdlib; Go-имена сохраняются: fmt.Println.
  • "./lib" — локальный пакет; путь без ведущей точки — Go-модуль; as — алиас.
  • Комментарии // и /* ... */; ; обязательна в конце statement.

04 Struct, методы, self

type Buffer = struct {
    data: u8[],
    name: str,

    fn Write(p: u8[]) int or error = {
        data = append(data, p...);
        return len(p);
    };

    fn Reset() void = {
        data = u8[] {};
    };
};
  • Поля и методы — внутри тела типа; поля разделяются запятыми.
  • self — неявный *T, в сигнатуре не пишется. Поля читаются по имени.
  • Если параметр или локальная переменная перекрывает поле — self.data.
  • Методы всегда с pointer receiver. Методов вне типа, value receiver, embedding и override нет.
  • Создание — var b = Buffer { data = u8[] {} }; вызов — b.Write(p) or return;
  • &T { ... } — heap-аллокация под GC; поля доступны через p.x.

05 Enum, match, type patterns

type Shape = enum {
    Circle { radius: f64 },
    Rect { w: f64, h: f64 },
    Empty,
};

fn area(s: Shape) f64 = {
    return match (s) {
    case Circle { radius } => 3.14159 * radius * radius;
    case Rect { w, h } => w * h;
    case Empty => 0.0;
    };
};
  • Варианты: Shape.Circle { radius = 2.0 }, без полей — Shape.Empty.
  • match по enum исчерпывающий, без fallthrough. Может быть выражением или statement.
  • Поля варианта связываются по имени: case Circle { radius }. При коллизии имён — case pkg.Circle { ... }.

Type patterns для any

fn update(msg: any) void = {
    match (msg) {
    case tea.KeyPressMsg as k => {
        if (k.String() == "q") { return; };
    };
    case tea.WindowSizeMsg => { ... };
    else => { ... };
    };
};
  • as k связывает значение с типом; case T — без привязки.
  • else — default для открытых типов; case _ в match нет. Enum всё равно должен быть исчерпан.

06 Ошибки и defer

T or error — ошибка как значение. error — Go-интерфейс.

fn read(path: str) u8[] or error = {
    var f = os.Open(path) or return;
    defer f.Close();
    var buf = u8[4096] {};
    var n = f.Read(buf[:]) or return;
    return buf[:n];
};

Три формы or

var f = os.Open(path) or return;

var data = os.ReadFile(path) or err {
    fmt.Println("read:", err) or return;
    return err;
};

os.Remove(path) or panic("cannot remove");
  • or — только statement-level: целый инициализатор, RHS, expression statement или операнд return. Внутрь выражения не вкладывается.
  • or panic() паникует со значением ошибки; or panic("...") — с сообщением.

Списки результатов

fn divmod(a: i32, b: i32) i32, i32 = {
    return a / b, a % b;
};

var q, r = divmod(7, 2);
  • fn f() A, B or error — форма объявления; ошибка идёт последней.
  • Тип функции с несколькими результатами: fn(i32) (str, bool).
  • Кортежа-значения нет: результаты раскладываются по именам, а не хранятся как одно значение.

defer блочный: срабатывает на выходе из ближайшего {}, в том числе через return, break, continue, or return и panic. Внутри par у каждого воркера свой DeferStack.

if (cache.Has(key)) {
    mu.Lock();
    defer mu.Unlock();
    ...
};

Ошибка Close значима — закрой явно: f.Close() or return;

if (x > 0) {
    ...
} else if (x == 0) {
    ...

    ...
};

for (var i = 0; i < n; i += 1) { ... };
for (var x in xs) { ... };
for (var i, x in xs) { ... };
for (var k, v in m) { ... };
for () { ... };
  • Условия в скобках; после блока-инструкции — ;.
  • break и continue есть; меток нет. switch нет: if или match.
  • match — выражение или statement; по enum исчерпывающий.
  • break из match-case пока запрещён — используй return или перестрой цикл.

08 Конкурентность

КонструкцияЧто делает
par { ... }независимые операторы, ждёт на }
par for (...) limit Nпараллельные итерации, N — ширина
within D { ... }дедлайн на блок
 
par {
    users = loadUsers(id) or return;
    orders = loadOrders(id) or return;
};

par for (var i = 0; i < len(urls); i += 1) limit 64 {
    sizes[i] = fetch(urls[i]) or return;
};

within 30s {
    par for (var i = 0; i < len(urls); i += 1) limit 64 {
        sizes[i] = fetch(urls[i]) or return;
    };
};
  • par ждёт на }; or return, or panic или паника отменяет остальные. Возвращается ошибка с низшим индексом statement; для par for — с низшим индексом итерации. Для map ord -1: побеждает первая дошедшая ошибка.
  • limit N — потолок одновременно выполняемых итераций; по умолчанию GOMAXPROCS.
  • within D — дедлайн на блок и всё, что он зовёт; работает без par; вложенность берёт минимальный дедлайн. Внутри воркера дедлайн не меняет соседей. Прерываются только вызовы, которые уважают ctx.
  • par: у захваченного корня один писатель, и никакой другой оператор его не читает. par for: писать можно только в слот по индексу итерации (срез/массив) или через sync/atomic. Запись через указатель, в map, в global и в self запрещена.
  • defer, within и or panic внутри работают: у каждого воркера свой DeferStack и recovery boundary; паника становится PanicError и отменяет блок.
  • return, break и continue не пересекают границу par; наружу — только or return/or panic.
  • context в коде нет: компилятор проводит скрытый _s_ctx; Go-функции с context.Context первым параметром получают его сами. На границе Go FFI — сгенерированный non-ctx wrapper.
  • Проверка статическая: алиасы из полей/индексов и function literals не отслеживаются; вызов метода на захваченном интерфейсе считается записью, а указатель/интерфейс в свободной или Go-функции — нет. Динамический оракул — go build -race (G11).

09 Go interop

  • use тянет Go-пакеты; имена остаются Go-именами.
  • Go-функции с context.Context первым параметром получают скрытый ctx автоматически.
  • Go-функция с (T, bool) — это var v, ok = f(); — не or.
  • Интерфейсы структурные: implements не нужен. Sema проверяет method set на присваивании/вызове (G27).
use os;

fn read(path: str) u8[] or error = {
    var f = os.Open(path) or return;
    defer f.Close();
    var buf = u8[4096] {};
    var n = f.Read(buf[:]) or return;
    return buf[:n];
};

use fmt;
use "charm.land/bubbletea/v2" as tea;

type Model = struct {
    count: int,

    fn Init() tea.Cmd = { return nil; };

    fn Update(msg: tea.Msg) tea.Model, tea.Cmd = {
        match (msg) {
        case tea.KeyPressMsg as k => {
            if (k.String() == "q") { return self, fn() tea.Msg => tea.Quit(); };
        };
        else => {};
        };
        return self, nil;
    };

    fn View() tea.View = { return tea.NewView(fmt.Sprintf("count: %d", count)); };
};

fn main() void or error = {
    var p = tea.NewProgram(&Model { count = 0 });
    p.Run() or return;
};

11 Границы 0.2

Не делаем

  • Нет go, chan, select, async, await, Promise: конкурентность только блоками.
  • Нет исключений: try/catch/?/!; ошибки — T or error.
  • Нет :=, let, export, атрибутов, switch, меток, UFCS, методов вне типа, embedding, перегрузки операторов.
  • Нет context в прикладном коде, unsafe, арен, RC/ORC, трейтов и lifetimes.
  • Нет tuple-значений: только списки результатов; результат нельзя хранить как одно значение.
  • Инфраструктуру — прокси, драйверы, брокеры — не пишем; берём из Go.

Ещё не в 0.2

  • Нет generic constraints и generic enum; параметр типа ведёт себя как any.
  • Нет локальных именованных функций — только function literals.
  • Нет variadic-объявлений (fn f(xs: T...)); Go-variadics вызывать можно.
  • case _ нет — else; break из match-case — ошибка.
  • or только statement-level; вложить в выражение нельзя.
  • Typecheck Go работает в strizh check и LSP на open/save; async/debounce (G43), колонки (G34) и тестовые пакеты — ещё нет.
  • par-проверки статические: map-записи запрещены всегда, алиасы из полей/индексов не отслеживаются; динамический оракул — go build -race (G11).
  • Method sets проверяются для Strizh/Go интерфейсов; generics, enum-варианты, массивы, function values и variadic остаются на go build (G27).
  • Strizh-функция или метод со скрытым ctx получает публичный wrapper на Go-границе; дедлайн не переносится через function value или пакет.

0.2 — preview, не 1.0. Полный список: design/GAPS.md.
