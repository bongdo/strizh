# Strizh — syntax v0

- **Статус:** исторический снимок v0 (до 0.2). Не источник истины: актуальная
  спецификация — [`SPEC.md`](SPEC.md).
- **Backend:** Go 1.26+.
- **Не зафиксировано на момент снимка:** частично `nil`, константы, модули,
  срезы, tooling.

Это не полная спецификация. Это снимок договорённостей и список того, что ещё
не решено. Документ не переписывается под новые решения; отказы собраны в
[`SPEC.md`](SPEC.md) §10.

---

## 0. Идентичность

Strizh = **Go runtime + Hare-подобный синтаксис + sum types + scoped parallelism**.

- Не системный язык с C backend. «C speed» не обещаем; обещаем Go speed,
  а в hot path — значения и срезы.
- Go-экосистема и stdlib доступны через `use`.
- В прикладном коде нет `unsafe`.
- Ошибки — значения, не исключения.
- Минимум синтаксиса: `var`, `;`, точка, `or`, `match`, `par`, `within`.

---

## 1. Лексика и видимость

- `;` обязателен в конце statement.
- Комментарии: `//` (Hare-style). Doc-комментарии не планируются.
- Видимость — как в Go, по регистру:
  - `User`, `Write`, `Name` — public;
  - `user`, `write`, `age` — private;
  - `main` — нижний регистр, но особая точка входа.
- Слова `export` нет. Слова `let`/`const`/`:=` нет.
- `@`-атрибутов нет. `::` нет.

---

## 2. Импорт

`use` — это import.

```hare
use fmt;
use os;
use sort;
use mypkg;
use mypkg as m;
```

- `use fmt;` — Go-пакет; дальше `fmt.Println`.
- `use mypkg;` — модуль Strizh; дальше `mypkg.Foo`.
- `use mypkg as m;` — алиас.
- Go-имена внутри импортированных пакетов остаются Go-именами:
  `fmt.Println`, `strings.ToUpper`, `os.Open`.

## 3. Типы

### 3.1. Постфиксные `[]`

Один вид скобок — `[]` — после типа. Он покрывает срезы, массивы и дженерики.

| Смысл | Синтаксис |
|---|---|
| срез / лист | `u8[]` |
| фиксированный массив | `u8[16]` |
| срез срезов | `u8[][]` |
| срез массивов | `u8[16][]` |
| массив срезов | `u8[][16]` |
| map | `map[str, User]` |
| generic-тип | `Stack[i32]` |
| generic-функция | `fn Map[In, Out](...)` |
| функция | `fn(i32) str` |
| указатель | `*T` |

Правило:

- `T[]` — срез (ноль параметров);
- `T[16]` — массив на 16;
- `T[U]` — generic-применение (U — тип);
- `map[K, V]` — встроенный generic-тип с двумя параметрами.

`Vec`/`List` нет: `T[]` и есть лист; растёт через `append`. Фиксированный
массив — `T[N]`.

Сложные случаи группируются `()`:

```hare
(*u8)[]          // срез указателей
*(u8[])          // указатель на срез
(fn(i32) str)[]  // срез функций
fn(i32) str[]    // функция, возвращающая срез
```

### 3.2. Базовые типы

- `void`, `bool`;
- `i8`, `i16`, `i32`, `i64`;
- `u8`, `u16`, `u32`, `u64`;
- `int`, `uint` — native (Go `int`/`uint`);
- `f32`, `f64`;
- `str` — Go `string`;
- `any` — top-тип (Go `any`);
- `error` — встроенный интерфейс для `T or error`.

Полный целочисленный набор и `usize`/`isize` — TBD; в примерах используются
`u8`, `u32`, `i32`, `int`.

### 3.3. Struct

Поля и методы — **внутри тела типа**.

```hare
type Buffer = struct {
    data: u8[],

    fn Write(p: u8[]) int or error = {
        data = append(data, p...);
        return len(p);
    };

    fn Reset() void = {
        data = u8[] {};
    };
};
```

- `self` — неявный `*T`; receiver в сигнатуре не пишется.
- Поля доступны по имени. Если имя перекрыто параметром/локальной — `self.data`.
- Методы всегда pointer receiver. Value receiver нет; для чтения по значению —
  свободная функция.
- Нет override, нет embedding. Метод-сет типа — ровно то, что в его теле.
- Метод нельзя добавить в другом файле.

### 3.4. Enum / sum type

```hare
type Shape = enum {
    Circle { radius: f64 },
    Rect { w: f64, h: f64 },
};

var s = Shape.Circle { radius = 2.0 };
```

`match` исчерпывающий:

```hare
return match (s) {
case Circle { radius } => 3.14159 * radius * radius;
case Rect { w, h } => w * h;
};
```

### 3.5. Interface

Интерфейсы — только на границе с Go; в app-коде полиморфизм через `enum` и
function values.

```hare
type Writer = interface {
    Write(p: u8[]) int or error;
};
```

- Методы внутри тела интерфейса, без `self`.
- Структурная реализация: `Buffer` с `fn Write` подходит без `implements`.
- Нет embedding, нет nil-interface чудес.

### 3.6. Generics

Опция 1: те же постфиксные `[]`, что у массивов.

```hare
type Stack[Item] = struct {
    data: Item[],

    fn Push(x: Item) void = {
        data = append(data, x);
    };

    fn Len() int = {
        return len(data);
    };
};

fn Map[In, Out](xs: In[], f: fn(In) Out) Out[] = {
    var out = Out[] {};
    for (var x in xs) {
        out = append(out, f(x));
    };
    return out;
};

var s = Stack[i32] {};
var ys = Map(xs, fn(x) => x * 2);            // In/Out выводятся
var zs = Map[i32, str](xs, fn(x) => ...);    // явно
```

- `T`, `U`, `Item`, `In`, `Out` — просто имена параметров; магии нет.
- На вызовах типы выводятся; явные аргументы — когда без них никак.
- Constraints (`comparable`, numeric) не планируются: параметр типа ведёт себя
  как `any`.
- `any` — не generic; это top-тип.

### 3.7. Указатели и `&`

`*T` — тип указателя. Создаётся только оператором `&`:

```hare
var p = &Node { x = 1 };     // новый объект в куче
var q = &nodes[i];           // указатель на элемент среза
var r = &local;              // адрес локальной переменной
```

- Поля читаются и пишутся через `p.x` (авто-разыменование, как в Go).
- Отдельного `*p` как значения в v0 нет — работай через поля.
- Указатели приходят из Go (`*http.Request`, `*File`) и уходят в Go.
- `&T { ... }` — обычная heap-аллокация под управлением GC. Отдельных арен нет.
- Ловушка: `&nodes[i]` + `append` к `nodes`. `append` может переехать в новый
  массив, и указатель останется смотреть в старый. Правило: не держи указатели
  на элементы среза, который растёт.
- `&local` не заставляет думать о стеке/куче: если значение убегает, Go сам
  переносит его в кучу.

## 4. Переменные и литералы

Только `var имя = значение;`. Тип — в значении.

```hare
var m = map[str, User] {};
var xs = u8[] {};
var xs2 = u8[] {1, 2, 3};
var a = u8[3] {1, 2, 3};
var u = User { Name = "Alice", age = 30 };
var s = Stack[i32] {};
var x = 1;
```

- `:=` нет.
- `var m: map[str, User] = {}` нет.
- `var` всегда с initializer. Нулевое значение — явно: `User {}`, `0`,
  `u8[] {}`, `map[str, User] {}`.
- Composite literal всегда несёт тип: `Type { ... }`.
- Пропущенные поля структуры — zero value (Go-style).
- Reassignment: `m["alice"] = ...;`, `xs = append(xs, 4);`.

### Map

- `map[K, V]` — всегда ключ и значение.
- Set — это `map[T, bool]`; проверка `if m["x"] { ... }`.
- Отсутствующий ключ возвращает zero value. Оператора `in` нет.
- Если когда-то понадобится «есть ли ключ» — функция `has(m, "x")`, не синтаксис.

### `nil` / zero

- `nil` имеет тип из контекста: `return nil;`, `f(nil)`, `x = nil`.
- Если контекста нет, тип обязателен: `var p = nil[*User]`, `nil[error]`,
  `nil[u8[]]`.
- `nil` допустим только для указателей, срезов, map, функций и интерфейсов.
- Для map/slice пустой литерал уже типизирован: `u8[] {}`, `map[K, V] {}`.

## 5. Функции и вызовы

```hare
fn area(r: f64) f64 = {
    return 3.14159 * r * r;
};

fn main() void or error = {
    var x = area(2.0);
    fmt.Println(x) or return;
};
```

- `fn name(args) Ret = { ... };`
- Несколько результатов — списком через запятую:
  `fn pair() i32, bool = { return 1, true; };`.
- `or error` добавляет последний результат-ошибку:
  `fn load() User, Order or error`.
- В типе функции несколько результатов группируются скобками:
  `fn(i32) (str, bool)`.
- `return` явный. Multi-result можно вернуть, связать (`var a, b = f();`) или
  присвоить (`a, b = f();`), но нельзя использовать как одно выражение.
- `main` может возвращать `void or error`; при ошибке рантайм печатает её и
  выходит с кодом 1.

### Вызовы

Правило: **точка выбирает, скобки вызывают. Одна форма на функцию.**

```hare
fmt.Println("hi");     // вызов
b.Write(p);            // метод
area(shape);           // свободная функция
var f = fmt.Println;   // значение функции, не вызов
```

- Метод объявляется внутри типа, вызывается на значении: `b.Write(p)`.
- Свободная функция: `area(s)`.
- UFCS нет: `area(s)` и `s.area()` — не обе формы.
- `Buffer.Write(b, p)` как вызов метода не используется.

### Замыкания

Замыкание — это function literal. Локальных именованных функций нет и не
планируется.

```hare
fn olderThan(users: User[], min: u32) User[] = {
    var older = fn(u: User) bool => u.age >= min;

    var out = User[] {};
    for (var u in users) {
        if older(u) {
            out = append(out, u);
        };
    };
    return out;
};
```

Inline-колбэк с выводом типов:

```hare
sort.Slice(users, fn(i, j) => users[i].age < users[j].age);
```

Блочная форма:

```hare
sort.Slice(users, fn(i, j) bool {
    return users[i].age < users[j].age;
});
```

Никаких `var f = fn...`, `=>`-лямбд с захватом через `var` и пайпов.

## 6. Ошибки

Тип: `T or error`.

```hare
fn read(path: str) u8[] or error = {
    var f = os.Open(path) or return;
    defer f.Close();
    var buf = u8[4096] {};
    var n = f.Read(buf[:]) or return;
    return buf[:n];
};
```

Три формы:

- `expr or return;` — если ошибка, вернуть её из текущей функции.
- `expr or err { ... }` — обработать здесь; `err` — имя ошибки.
- `expr or panic("...");` — развернуть, упасть.

```hare
var data = read("x") or err {
    fmt.Println("read failed:", err) or return;
    return err;
};
```

- Никаких `try`/`catch`, `?`, `!`.
- Ошибки — значения; `or` — сахар над проверкой.
- `if (err != nil) { return err; }` и multi-result вариант — ошибка: проброс
  пишется только через `or return`. `if err != nil` остаётся для инспекции,
  логирования, retry и `errors.Is`.
- `defer` — cleanup на выходе из блока, включая ошибки (§7).
- `error` — Go-интерфейс; `errors.New` доступен через `use errors;`.

## 7. Control flow

```hare
if (x > 0) {
    ...
} else {
    ...
};

for (var i = 0; i < n; i += 1) {
    ...
};

for (var x in xs) {
    ...
};

match (shape) {
case Circle { radius } => ...;
case Rect { w, h } => ...;
else => ...;
};
```

- `match` исчерпывающий; без fallthrough.
- Для `any`/интерфейсов — type-паттерны `case T as x => ...`, `case T => ...`;
  `else => ...` — default. Для enum остаются variant-паттерны.
- `switch` нет; для значений — `if`/`match`.
- `break`/`continue` есть.
- `defer` — **блочный**: срабатывает на выходе из ближайшего `{}`, а не из
  функции. Поэтому блокировка корректна по построению:

```hare
if (cache.Has(key)) {
    mu.Lock();
    defer mu.Unlock();   // сработает на `}`, а не в конце функции
    ...
};
```

- В теле функции `defer` и блочный, и функциональный дают одно и то же —
  но только блочный не превращает `defer` в цикле в утечку дескрипторов.
- `defer` не возвращает ошибок. Значимую ошибку закрытия пиши явно:
  `f.Close() or return;` перед `return`.
- Кодоген: `defer` на верхнем уровне тела функции → обычный Go `defer`;
  `defer` во вложенном блоке или цикле → блок оборачивается в замыкание,
  `return`/`break`/`continue` наружу идут сигналом. Детали и замеры — §10.8.

## 8. Go interop

- `use` импортирует Go-пакеты; Go-имена сохраняются.
- Методы/интерфейсы/дженерики/`any`/`error` — поддерживаются, потому что
  иначе Go-экосистема недоступна.
- `context` в app-коде не появляется; `par`/`within` прячут его (§10.7).
- Кодоген в Go:
  - `//line`-директивы, чтобы stack traces/Delve показывали Strizh-файлы;
  - `go/format`.
- `unsafe` не нужен ни в кодогене, ни в прикладном коде.
- Маппинг типов:

| Strizh | Go |
|---|---|
| `str` | `string` |
| `u8` / `u16` / `u32` / `u64` | `uint8` / `uint16` / `uint32` / `uint64` |
| `i8` / `i16` / `i32` / `i64` | `int8` / `int16` / `int32` / `int64` |
| `int` / `uint` | `int` / `uint` |
| `f32` / `f64` | `float32` / `float64` |
| `T[]` | `[]T` |
| `T[N]` | `[N]T` |
| `map[K, V]` | `map[K]V` |
| `*T` | `*T` |
| `any` | `any` |
| `fn(A) B` | `func(A) B` |
| `T or error` | `(T, error)` |
| `interface` | Go interface |
| `enum` | tagged struct/interface (TBD) |

- Методы внутри Strizh-типа кодоген выносит наружу:
  `fn Write` → `func (self *T) Write`.
- Видимость по регистру совпадает с Go: `Write` → `Write`, `write` → `write`.

## 9. Арены: отдельной конструкции нет

Арена — это срез с запасом и указатели в него. Язык это уже умеет:

```hare
var pool = Node[] {};

for (var frame = 0; frame < 60; frame += 1) {
    pool = pool[:0];                 // освободить всё разом, память осталась
    for (var i = 0; i < n; i += 1) {
        pool = append(pool, Node { x = 0 });
    };
};
```

Или фиксированный массив, когда ёмкость известна:

```hare
var pool = Node[10_000] {};
var p = &pool[i];
```

Замеры на 100 000 узлов (Go 1.26.3):

| Способ | ns/op | allocs/op |
|---|---|---|
| каждый узел отдельно | ~4.9–5.6 ms | 100 000 |
| `[]T` с запасом + `append` | **~0.59 ms** | **0** |
| `[]T` заново на каждый вызов | ~1.7 ms | 1 |

Почему конструкции нет:

- `[]T` даёт то же ускорение без `alloc`, без проверки убегания и без
  «менеджера памяти» в языке.
- Для `T` без указателей GC и так не сканирует содержимое среза — это уже
  бесплатно.
- Связные структуры в value-языке пишутся индексами, и это быстрее
  указателей: обход идёт по памяти подряд.
- `arena T(n) { alloc() }` добавляла бы ровно одно: указатели с временем жизни
  блока. Это ниша, а не общая задача.

`unsafe` в прикладном коде не нужен и не появится.

## 10. Многопоточка

Модель: структурная конкурентность + невидимый async. В прикладном коде нет
`go`, `chan`, `select`, `async`, `await`, `Future` и `context.Context`.

### 10.1. I/O не требует ничего

Блокирующий вызов блокирует только свою горутину. HTTP-обработчик — обычная
линейная функция; Go сам даёт горутину на соединение. Никаких `async`/`await`,
поэтому функция не «красится» и сигнатуры не заражаются.

### 10.2. `par { }` — независимые операторы

```hare
par {
    users = loadUsers(id) or return;
    orders = loadOrders(id) or return;
};
```

- Операторы внутри считаются независимыми и выполняются параллельно.
- На `}` блок дожидается всех. Утечь нечему: конкурентность не переживает блок.
- Ошибка (`or return`/`or panic`) или паника в одном — отменяет остальные.
  Индексированные воркеры отдают ошибку с наименьшим ord; в `void`-функции
  победившая ошибка перепаникуется на выходе из блока.
- Каждый воркер имеет свою границу recovery: паника превращается в
  `PanicError` (значение + stack), добавляется в ошибки блока и отменяет
  соседей. `Wait` при этом завершается.
- `defer`, `within` и `or panic` внутри `par` разрешены. У каждого воркера свой
  `DeferStack`; отложенные вызовы идут LIFO на выходе воркера и до отчёта об
  ошибке. `defer` на верхнем уровне тела `par` — отдельный воркер: оберни его
  в блок, если очистка относится к соседним операторам.
- Вложенный `par` разрешён.

### 10.3. `par for` — параллельные итерации

```hare
par for (var i = 0; i < len(urls); i += 1) limit 64 {
    sizes[i] = fetchSize(urls[i]) or return;
};
```

- `limit N` — потолок одновременно выполняемых итераций; по умолчанию
  `GOMAXPROCS`. Семафор внутри рантайма, наружу не виден.
- Ошибка отменяет остальные итерации; возвращается ошибка с **наименьшим
  индексом** — одинаковый баг даёт одинаковое сообщение. Для map индекса нет:
  все итерации отдают ord `-1`, побеждает первая дошедшая ошибка, порядок
  недетерминирован.
- `par for (var x in xs)` работает так же.
- Порядок результатов определяет вызывающий код, не порядок завершения.

### 10.4. `within D { }` — дедлайн

```hare
within 30s {
    par for (var i = 0; i < len(urls); i += 1) limit 64 {
        sizes[i] = fetchSize(urls[i]) or return;
    };
};
```

- Ставит дедлайн на неявный контекст блока; Go-функции, принимающие
  `context.Context` первым аргументом, получают его автоматически.
- Работает и без `par`.
- Внутри `par`/`par for` дедлайн принадлежит воркеру: он выводится из общего
  cancel-контекста блока, не меняет контекст соседей, но отмена соседей
  отменяет и его.
- Вложенность: действует минимальный дедлайн.
- Дедлайн грубее, чем на отдельный вызов: прерываются только те вызовы,
  которые уважают `ctx`.

`limit` и `within` — раздельные конструкции: `limit` ограничивает ширину
конкретного цикла, `within` — область работы целиком (подготовка, цикл,
свёртка). Оба одновременно — обычное дело (batch с SLA).

### 10.5. Гонки

Правила для `par` и `par for` разные; проверка статическая.

Для `par` на каждый top-level оператор считаются captured read/write sets.
Захваченный корень может писать не более одного оператора, и никакой другой
оператор не может его читать. Прямые алиасы (`var q = p`, `q = p`)
приписываются корню.

Для `par for` запись в захваченный корень запрещена, кроме непересекающегося
слота `base[i]`, `base[i].f` или `base[i][j]`, где цепочка индексов — срез или
массив, а внешний индекс содержит переменную итерации.

```hare
var total = 0;
par {
    total = loadA();  // один писатель
    print(total);     // ошибка: другой оператор читает total
};

var parts = int[n] {};
par for (var i = 0; i < n; i += 1) {
    parts[i] = i; // ок: слот принадлежит итерации
};
```

- Запись через захваченный указатель (`*p`, `p.f`, `p[i]`, `p.M()`), в слот
  захваченного map, в global и в `self` запрещена в обеих формах. Для map —
  даже при разных ключах: `writing to map <root> inside par`. Global общий
  для всей программы, поэтому одного writer'а недостаточно.
- Проверка синтаксическая: индекс обязан быть переменной итерации.
  `counts[i % 8] += 1` отвергается — дизъюнктность не доказуема.
  Для шардированного счётчика — массив `atomic.Int`.
- Алиасы из полей, индексов и результатов вызовов не отслеживаются; запись
  внутри function literal не анализируется; вызов метода на захваченном
  интерфейсе считается записью, а указатель/интерфейс, переданный в свободную
  или Go-функцию, не отслеживается. Динамический оракул — `go build -race`
  (G11).
- Никаких `Send`/`Sync` трейтов, `Arc<Mutex<T>>`, lifetimes.

### 10.6. Мьютексы

Язык их не предоставляет. `use sync;` — обычный Go-тип, нужен редко:

| Случай | Решение |
|---|---|
| Собрать результаты (90%) | слоты + последовательная свёртка, локов нет |
| Общий кэш/конфиг, читают часто | неизменяемый снимок + `atomic.Pointer[T]` |
| Общее изменяемое состояние с инвариантом | `sync.Mutex` |

Мьютекс — ровно та редкая вещь, которая **должна** напоминать о
многопоточке. Прятать его за синтаксисом языка нельзя: тогда перестаёшь
замечать, что делишь память.

### 10.7. `context` не существует

`par`/`within` создают контекст сами, отменяют его при ошибке, панике и
выходе из функции. В Strizh-коде `ctx` не пишется нигде: ни в сигнатурах,
ни в вызовах, ни в типах. Кодоген подставляет его в Go-вызовы, у которых
он первый параметр.

На границе Go-интерфейса (например, `tea.Model.Update`) кодоген генерирует
публичную обёртку с точной Go-сигнатурой и внутреннюю ctx-версию. Пользователь
пишет один метод; обёртка скрыта в `zz_strizh.go` (G10).

### 10.8. Кодоген и замеры

Проверено на Go 1.26.3:

| Что | Результат |
|---|---|
| `defer` в блоке без обёртки | неверно: срабатывает в конце функции |
| замыкание на итерацию, без `defer` | инлайнится, стоимость 0 (447 vs 452 ns/1000) |
| замыкание на итерацию, с `defer` | +3.3 ns/итерацию, 0 аллокаций |
| `defer` на верхнем уровне функции | плоский Go `defer`, стоимость 0 |
| `par for` арм | уже замыкание-горутина, `defer` бесплатен |

`par` → `WaitGroup` + `context.WithCancel` (создаётся всегда) + recovery
boundary на воркер; у каждого воркера свой `DeferStack` и свой ctx slot.
Ошибки и паники идут в `ParErrors`; после `Wait` побеждает `First()` —
минимальный ord, а для map (`-1`) первая дошедшая ошибка. `par for` →
горутины с семафором `limit`; ord растёт на итерацию, map отдаёт `-1`.
`no inline` у замыкания с `defer` — причина +3.3 ns (`unhandled op DEFER`),
лечится только выносом `defer` на верхний уровень функции.

`or return` внутри обёрнутого блока — не редкий случай, а норма: каждый
`or return` в теле цикла с `defer` идёт через кадр-сигнал
(`kind` + значение + ошибка), который протаскивается через вложенные `if`.
Это работа компилятора, не рантайма.

### 10.9. Чего нет и почему

| Нет | Почему |
|---|---|
| `go` | запуск без владельца |
| `chan`, `select`, `<-` | протокол вместо «сделай параллельно» |
| `async`/`await`/`Promise` | цвет функций, вирус в сигнатурах |
| `Send`/`Sync` | налог на понимание без выгоды для приложений |
| `task.run`, хендлы | конкурентность живёт внутри блока |
| worker pool API | сводится к `limit N` |

Известные дыры (приемлемы для приложений, не для инфраструктуры):

- потоковая обработка без материализации — через `iter.Seq[T]` из Go,
  но без параллелизма;
- producer/consumer с заранее неизвестным числом задач;
- акторы, pub/sub, приоритеты, свои планировщики;
- «найти первого и выйти» — есть `return`, нет `break` с результатом;
- map-итерация не имеет ord: побеждает первая дошедшая ошибка, порядок
  недетерминирован;
- stack паники — это stack на recovery boundary воркера, а не обязательно
  место `panic`;
- алиасы из полей/индексов и записи в function literal не анализируются;
  запись в map запрещена всегда, даже по разным ключам;
- динамического race detector в компиляторе нет: `go build -race` — оракул
  (G11).

Инфраструктуру (прокси, драйверы, брокеры) на Strizh не пишем — берём из Go.

## 11. Что явно отклонено

- `try`/`catch`, `?T`, `none`;
- `export`, `let`, `const`, `:=`;
- `@`-атрибуты, `::`;
- `borrow`, `shared`, `weak`;
- `in` для map;
- `<>` для дженериков;
- методы снаружи типа, UFCS;
- `go`, `chan`, `select`, `<-`;
- `async`, `await`, `Promise`, `Future`;
- `Send`/`Sync` трейты, `scope`, `task.run`;
- `arena`, `alloc`, `unsafe`;
- RC/ORC, C backend как основной.

## 12. Открытые вопросы

**Типы и значения**

- `nil`: решено — bare `nil` при известном типе, иначе `nil[T]`.
- Размер целых: `usize`/`isize` vs `int`/`uint`.
- Переполнение, деление на ноль, конверсии `u64(x)`.
- Константы: `const` отклонён, а именовать числа нечем — нужен ли отдельный
  неизменяемый `var`/`enum`-вариант.
- `*p` как значение и присваивание `*p = ...` (пока только поля через `p.x`).

**Срезы и контейнеры**

- Срезы: `a[i:j]`, `cap`, `copy`, ёмкость (`make` или иная форма).
- Итерация по map: только ключи или `for (var k, v in m)`.
- `iter.Seq2` — если появится двухпеременный `for`.

**Функции и полиморфизм**

- `any` и type switch / `match` по `any`: решено — `case T as x` + `else`.
- Method/field name collisions; nil-интерфейс.
- `enum` codegen: tagged struct vs interface; производительность.

**Модули и процесс**

- `use mypkg`: где ищется пакет, как группируются файлы, `strizh.toml`.
- Верхнеуровневые `var` и порядок инициализации.
- Строковые escapes, интерполяция.
- Build/tooling: `strizh build/run/test`, LSP.
- Тесты: синтаксис `test`-функций.
- FFI: cgo/manifest; не приоритет.
- Многопоточка: потоки без материализации и параллельные пайплайны — когда
  понадобятся.

### Not planned

Эти пункты обсуждались в v0, но реализованы не будут. Канонический список —
[`SPEC.md`](SPEC.md) §10.

- Generic constraints (`comparable`, numeric).
- Doc-комментарии, привязанные к объявлению.
- Локальные именованные функции.

## 13. Пример целиком

```hare
use fmt;
use os;
use sort;

type User = struct {
    Name: str,
    age: u32,

    fn Greet() str = {
        return "hi, " + Name;
    };
};

type Shape = enum {
    Circle { radius: f64 },
    Rect { w: f64, h: f64 },
};

fn area(s: Shape) f64 = {
    return match (s) {
    case Circle { radius } => 3.14159 * radius * radius;
    case Rect { w, h } => w * h;
    };
};

fn read(path: str) u8[] or error = {
    var f = os.Open(path) or return;
    defer f.Close();
    var buf = u8[4096] {};
    var n = f.Read(buf[:]) or return;
    return buf[:n];
};

fn main() void or error = {
    var users = User[] {
        User { Name = "Alice", age = 30 },
        User { Name = "Bob", age = 25 },
    };

    sort.Slice(users, fn(i, j) => users[i].age < users[j].age);

    for (var u in users) {
        fmt.Println(u.Greet()) or return;
    };

    var data = read("users.txt") or err {
        fmt.Println("read failed:", err) or return;
        return err;
    };

    fmt.Println(len(data)) or return;
};
```
